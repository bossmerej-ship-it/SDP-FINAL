# Подключение React к Java

В проекте подготовлена граница интеграции RestaurantFacade.
Будущий HTTP-контроллер принимает JSON, создаёт OrderRequest и возвращает
OrderView или PriceBreakdown. Классы паттернов используются через тот же фасад.

## Предлагаемые HTTP-маршруты

Это план будущего API. Сейчас запускается Java Demo.

| Метод и путь | Метод Java |
|---|---|
| GET /api/menu | facade.getMenu() |
| POST /api/orders/quote | facade.quote(request) |
| POST /api/orders | facade.placeOrder(request) |
| GET /api/orders/{id} | facade.getOrder(id) |
| GET /api/orders | facade.listOrders() |
| PATCH /api/orders/{id}/status | facade.updateStatus(id, status) |

Пример тела POST /api/orders:

```json
{
  "customer": "Aida",
  "serviceType": "TAKEAWAY",
  "tableNumber": null,
  "comment": "Please pack napkins",
  "discount": "student",
  "items": [
    { "meal": "burger", "toppings": ["cheese", "sauce"], "quantity": 1 }
  ]
}
```

Результат содержит id, customer, serviceType, tableNumber, comment, items,
price (subtotal, discount, total) и status. Цена рассчитывается в Java
по кодам блюд и добавок. Клиент передаёт выбор, количество и параметры заказа.

## Порядок интеграции

1. Добавьте HTTP-слой Java, например контроллеры Spring Boot, и одну общую
   инстанцию RestaurantFacade на приложение.
2. Преобразуйте JSON в records из api/. Ошибки ввода верните с понятным сообщением.
   Для отсутствующего заказа можно выделить отдельное исключение и ответ 404,
   для неправильных полей — 400, для недопустимого перехода — 409.
3. На React реализуйте меню, добавки, корзину и отправку OrderRequest.
4. Экран кухни получает список заказов и отправляет новый статус.
5. Страница клиента получает состояние своего заказа через GET.
   При необходимости подписчик Observer может пересылать события через SSE.
6. Перед публичным использованием добавьте постоянное хранилище, идентификаторы
   пользователей и проверку доступа к заказам. Совпадение имени в CustomerObserver
   — удобство демонстрации, а для веб-авторизации нужен проверенный customerId.

## Что учесть

- Все данные живут в памяти. Перезапуск создаёт пустое хранилище.
- quote() только рассчитывает цену. placeOrder() каждый раз создаёт новый заказ.
  Для повторной отправки HTTP-запросов можно добавить idempotency key.
- Скидка student в учебном примере выбирается явно. Проверку права на неё следует
  добавить на сервере при реальной интеграции.
- Методы OrderService синхронизированы. Текущие подписчики быстрые и локальные.
  Сетевой вызов внутри callback задержит другие операции. Доставку по сети
  следует вынести из обработки заказа.
- Подписчик должен обрабатывать полученное событие и не менять заказы внутри
  callback. Это сохраняет простой последовательный порядок событий.
- Веб-слой должен определить ограничения размера запросов, число позиций
  и допустимые номера столов для конкретного ресторана.
