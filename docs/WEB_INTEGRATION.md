# Веб-интерфейс и подключение к Java

Интерфейс уже подключен: JDK 17 HttpServer раздает статические HTML/CSS/JS и
обрабатывает HTTP-запросы. Одна общая инстанция RestaurantFacade создает блюда,
применяет добавки и скидки, хранит заказы и управляет состояниями.

Запуск: `./run-web.ps1` (Windows) или `sh ./run-web.sh` (macOS/Linux).
По умолчанию — http://127.0.0.1:8080. Сервер слушает только loopback.
Внешних библиотек, сборки frontend, JSON-парсера и базы данных нет.

## Страницы

| Путь | Назначение |
|---|---|
| `/` | Меню, добавки, корзина, оформление |
| `/orders` | Заказы текущей браузерной сессии и состояние приготовления |
| `/kitchen` | Все заказы локального приложения, управление приготовлением |
| `/assets/*` | Локальные CSS, JS и фотографии |

## Реальные HTTP-маршруты

Ответы API — JSON в UTF-8; деньги — JSON-числа из Java BigDecimal.
**Тела POST — формы application/x-www-form-urlencoded, не JSON.**

| Метод и путь | Результат / метод Java |
|---|---|
| GET `/api/session` | `{csrfToken}`, создание cookie сессии |
| GET `/api/menu` | `{meals,toppings,studentDiscountPercent}`, facade.getMenu() |
| POST `/api/orders/quote` | `{subtotal,discount,total}`, facade.quote(request) |
| POST `/api/orders` | OrderView, 201, facade.placeOrder(request) |
| GET `/api/orders` | Список заказов текущей сессии |
| GET `/api/orders/{id}` | Заказ текущей сессии или 404 |
| GET `/api/kitchen` | Все заказы, facade.listOrders() |
| POST `/api/orders/{id}/status` | OrderView, facade.updateStatus(id,status) |

После GET /api/session браузер сохраняет HttpOnly/SameSite=Strict cookie;
каждый POST передает токен в заголовке X-CSRF-Token. Если указан Origin,
он должен совпадать с текущим loopback-адресом и портом.

Пример формы для одной позиции (значения здесь приведены до URL-кодирования):

```text
customer=Айда
serviceType=TAKEAWAY
comment=Положите салфетки
discount=student
meal=burger
quantity=1
cheese=1
sauce=1
```

Для нескольких строк повторяются meal, quantity, cheese, sauce — по одному
значению каждого поля на строку, в одинаковом порядке. cheese и sauce — число
порций добавки на одно блюдо; quantity — число блюд. Для DINE_IN передается
tableNumber; для TAKEAWAY поле отсутствует или пустое. Клиентские цены сервер
не принимает. Quote не сохраняет заказ.

Ответ OrderView содержит id, customer, serviceType, tableNumber, comment,
items (description, quantity, unitPrice, lineTotal), price
(subtotal, discount, total) и status.

Форма обновления состояния: `status=PREPARING` или `status=READY`.
Допустимы NEW → PREPARING → READY и повтор текущего состояния.
Другие переходы возвращают 409.

POST создания также принимает Idempotency-Key (до 128 символов из
букв, цифр, ._:-). В одной сессии повтор ключа с тем же телом возвращает
сохраненный результат; с другим телом — 409. Последние 100 ключей хранятся
в памяти сессии. Браузер сохраняет ключ неудачной отправки и использует его
при повторе неизмененного заказа; автоматического повтора POST нет.

## Ошибки и ограничения

Ошибка: `{"error":"Сообщение на русском"}`. Ответы: 400 — поля формы;
403 — CSRF/Origin; 404 — путь или недоступный заказ; 405 — метод;
409 — переход статуса/повтор ключа с измененным телом; 413 — размер;
415 — неверный Content-Type.

Имя 1–100 символов, комментарий до 500; до 30 строк, 1–99 блюд в каждой,
0–20 порций каждой добавки, номер стола 1–9999. Тело до 32 КБ.
Статические файлы проверяются на обход директорий и ссылки; ответы задают
Content-Type, nosniff и CSP. Клиент помещает пользовательский текст через textContent.

JS загружает меню, управляет черновиком корзины и вызывает серверный quote.
Он не заменяет бизнес-правила Java. Список заказов и кухня запрашиваются
каждые 5 секунд без перекрывающихся фоновых запросов; скрытые страницы не опрашиваются.
Нативные HTML-формы проверяют поля, сервер проверяет их независимо.

## Границы учебного приложения

Заказы и сессии существуют до остановки Java-процесса. Корзина и черновик
сохраняются в sessionStorage текущей вкладки; при запрете storage работают до перезагрузки.
Заказы разделены случайной cookie, а не именем клиента. Кухня доступна всем
локальным пользователям приложения без отдельной авторизации. Оплата,
доставка и проверка статуса студента не реализованы и не показаны в интерфейсе.

## Проверки

`./test.ps1` или `sh ./test.sh` компилирует с --release 17 -Xlint:all и выполняет
restaurant.RestaurantTests, затем restaurant.WebTests. HTTP-проверки поднимают
настоящий сервер на свободном порте с отдельным хранилищем и тестовой статикой.
